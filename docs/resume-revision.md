## 1. 项目简介

**原条目:**

> 设计并开发了一款桌面端 AI 智能剪辑产品,是面向音视频剪辑场景的垂类智能体,采用混合云架构,支持自然语言输入一键生成完整短视频,支持本地零样本音色克隆,完整覆盖从创意输入到成片导出的全流程,帮助创作者将制作周期从小时级缩短到分钟级。

**修改后:**

> 设计并开发了一款桌面端 AI 智能剪辑产品,是面向音视频剪辑场景的垂类智能体:输入一段文字,自动完成选题拆解、分镜规划、素材匹配、配音、字幕与合成,一键生成完整短视频;采用「在线 + 本地」混合云架构与本地零样本音色克隆,素材与参考音频不出本机;关键节点支持人工确认与打回修改,覆盖从创意输入到成片导出的全流程,将制作周期从小时级缩短到分钟级。

**原因**:原条目基本属实(混合云、零样本克隆、全流程都核实过),但丢了本项目最值钱的差异化——**人机协同**(分镜确认/打回)和**数据不出端**。这两点是面试官判断"这不是套壳 demo"的关键,放进简介里。

---

## 2. 架构设计

**原条目:**

> 主导整体架构设计,采用 pnpm Monorepo 分层架构,清晰划分「界面层 / 智能体层 / 音视频层 / 桌面底层」四层职责,基于 Zod 实现全链路数据校验,从输入到输出每一层都有格式保障,有效规避 LLM 输出不稳定问题,将线上格式错误率降低 90% 以上。

**修改后:**

> 主导整体架构设计,采用 pnpm Monorepo 分层架构,划分「界面层 / 智能体层 / 音视频层 / 桌面底层」四层职责,依赖方向单向,智能体层与 Electron 解耦、可在纯 Node 环境单测;基于 Zod 实现全链路数据校验——LLM 结构化输出在 Provider 层解析即校验,工程产物另有完整 Schema 双重复核,非法输出在进入下一节点前即被拦截,系统性规避 LLM 输出不稳定问题。

**原因**:🔴 删掉「90% 以上」——没有任何基线数据支撑,被问"怎么测的"必崩。改成机制描述,同时补充"智能体层解耦可单测"这个真实且能勾起兴趣的点。

---

## 3. 智能体设计

**原条目:**

> 基于 LangGraph.js 设计实现了完整的剪辑智能体工作流,包含素材扫描、创意生成、分镜规划、分镜审批中断、素材匹配、语音合成、时间线组装全链路;利用 Checkpoint 持久化机制实现断点续跑,支持用户修改分镜后从中断处继续执行,保留所有中间状态,提升人机协作体验。

**修改后:**

> 基于 LangGraph.js 设计实现剪辑智能体工作流,覆盖素材扫描、多模态素材理解、创意生成、分镜规划、分镜审批中断、素材匹配、语音合成、时间线组装全链路;利用 Checkpoint(SqliteSaver)持久化实现断点续跑,App 重启后可从中断处继续执行、保留全部中间状态;用户打回分镜并附反馈时,Agent 携带反馈跳回规划节点重新拆分镜而不重头执行;多模态理解结果持久化复用,相同素材不重复调用模型,节省 token 与等待时间。

**原因**:原条目属实。补三个被忽略的真实亮点:① 多模态素材理解(Agent 真"看"画面);② reject 反馈回路(跳回重跑不重头);③ 多模态结果持久化复用(把删掉的"缓存/降本"叙事挪到这里,用真实机制支撑)。

## 4. 音视频导出

**原条目:**

> 设计实现了类型安全的 FFmpeg 命令构建器,将多轨道时间线自动转换为 `filter_complex` 复杂滤镜图,系统化解决了 atempo 变速串联、Windows 路径转义、字幕字体跨平台兼容、PTS 时间戳对齐等常见工程坑点;实现了 stderr 进度解析和 AbortController 全链路取消,前端实时展示百分比和剩余时间,支持用户随时终止并自动清理临时文件,不会残留僵尸进程。

**修改后:**

> 设计实现类型安全的 FFmpeg 命令构建器,将多轨道时间线自动转换为 `filter_complex` 复杂滤镜图,系统化解决 atempo 变速串联、Windows 路径转义、字幕字体跨平台兼容、PTS 时间戳对齐、短源素材自动循环等工程坑点;解析 stderr 输出实时计算导出百分比;FFmpeg 导出链路支持 AbortController 全链路取消(终止即 SIGTERM 杀子进程、Windows 无孤儿进程风险),自动清理临时目录,退出不残留进程。

**原因**:🔴「全链路取消」只对导出链路成立(Agent 图取消是协作式),改成"FFmpeg 导出链路";🔴「剩余时间」代码里不存在(只有百分比 + 总时长),删掉。✅ 补上「短源素材自动循环」——这是真实且少见(预览/导出语义一致性)的亮点,面试官会追问。

## 5. TTS 架构设计

**原条目:**

> 设计了「在线 + 本地」混合云 TTS 架构,抽象出与厂商无关的统一 Provider 接口,默认走火山在线 TTS 保证音质,自定义音色走本地 Index-TTS 2 保护用户隐私;实现了基于内容哈希的语音缓存和 LRU 淘汰,相同内容不重复调用,大幅降低 API 调用成本,提升重复场景响应速度 10 倍以上。

**修改后:**

> 设计「在线 + 本地」混合云 TTS 架构,抽象厂商无关的统一 Provider 接口,按音色类型路由:默认走火山在线 TTS(seed-tts)保证音质与并发,自定义音色走本地 Index-TTS2 零样本克隆——参考音频不出本机,保护用户隐私;实现本地音色库,支持上传/录制参考音频并在工程内复用。

**原因**:🔴 整段「内容哈希缓存 + LRU + 10 倍提速」在代码里不存在,删除。降本叙事已由第 3 条(多模态理解持久化复用)用真实机制承接。剩下部分全部属实,保留即可。

**原条目:**

> 在项目中实践了 AI 时代的混合开发流程:探索阶段使用 Vibe Coding 快速验证方向,稳定阶段切换到 Spec Driven 开发保证质量,平衡探索效率和工程质量,充分发挥 AI 提效优势同时控制技术债务。

## 8. 面试追问应对(改完简历后必看)

| 新条目可能带来的追问 | 标准回答要点 |
|---|---|
| "多模态理解怎么持久化复用的?" | `asset_understandings` 表,`ON CONFLICT (run_id, asset_id) DO UPDATE`,启动时对未终态 run 热加载;按 runId 隔离不串数据 |
| "打回分镜的跳转怎么实现的?" | `Command({ goto: 'plan_scenes', update: { sceneApprovalFeedback, scenes: [] } })`,feedback 透传给 LLM,scenes 清空防脏数据 |
| "短源循环怎么保证预览和导出一致?" | 导出 `-stream_loop -1` + setpts 偏移 + 外层 trim;预览 HTML5 video loop;loop 输入不能用 `trim=end`(第一轮就截断) |
| "Provider 路由规则?" | `RoutingTtsProvider`:voiceId 带 `custom:index-tts2:` 前缀走本地,否则走火山;本地 Gradio 服务需探活,失败有降级路径 |
| "Spec Driven 产物长什么样?" | `docs/superpowers/` 下 plan(阶段拆解)+ spec(需求/设计/验收),先文档后实现 |
| "零样本克隆怎么做到的?" | IndexTTS2 是零样本模型,参考音频 + 文本 → 合成,无需训练;音色库存参考音频文件,导出时经 provider 再合成 |

> 更完整的答题要点见 `docs/interview-prep.md` 的 §7.5(简历专项追问)与 §1.5(简历逐条核对表)。
